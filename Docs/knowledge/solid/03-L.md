# Liskov Substitution Principle (LSP)

## What it is

Anything that claims to implement a contract must be **usable wherever that contract is expected** — same preconditions, postconditions, and error meaning. Callers should not need `if (adapter === "mariadb")` to stay correct.

| Contract promise | LSP-safe | LSP break |
|------------------|----------|-----------|
| `get(id)` missing → `null` | All adapters return `null` | One throws, one returns `null` |
| `add` persists durably | All flush before resolve | One resolves before write |
| `delete` removes or errors | Consistent | One no-ops silently |

## When to use

### Backend (Hono)

- Multiple DB adapters behind one repository port
- In-memory fake used in tests must behave like production for the methods under test

### Frontend (React)

- Swapping storage (`localStorage` vs Capacitor Preferences vs API) behind one client interface
- Polymorphic UI props (`Icon` variants) that must honor the same accessibility contract

## When not to use

- Forcing unrelated types under one interface just to reuse a helper name
- Deep inheritance trees when composition is clearer
- One “god” interface that no implementation can honor fully (fix with [04-I.md](04-I.md))

**Rule of thumb:** if substituting B for A requires the caller to special-case B, LSP is broken (or the interface is too wide).

## Backend (Hono) — worst practice

Same port, incompatible behavior. Use cases and routes cannot trust the abstraction.

```ts
export interface TodoRepository {
  get(id: string): Promise<Todo | null>;
  delete(id: string): Promise<void>;
}

// ❌ LibSQL: missing → null (matches docs)
export class LibSqlTodoRepository implements TodoRepository {
  async get(id: string) {
    const row = await this.client.get(id);
    return row ? mapTodo(row) : null;
  }
  async delete(id: string) {
    await this.client.execute("DELETE FROM todos WHERE id = ?", [id]);
  }
}

// ❌ Postgres: missing → throw (callers blow up)
export class PostgresTodoRepository implements TodoRepository {
  async get(id: string) {
    const row = await this.client.query("…", [id]);
    if (!row) throw new Error("not found"); // different contract!
    return mapTodo(row);
  }
  async delete(id: string) {
    // ❌ silent no-op — caller thinks delete succeeded
    return;
  }
}
```

```ts
// Caller assumes LSP — breaks on Postgres
app.delete("/todos/:id", async (c) => {
  const todo = await todos.get(c.req.param("id"));
  if (!todo) return c.json({ code: "NOT_FOUND" }, 404); // never hit on PG throw path
  await todos.delete(todo.id);
  return c.body(null, 204); // lies if delete no-ops
});
```

## Backend (Hono) — best practice

Document the contract; every adapter (and the test fake) honors it. Use **capability flags** for real vendor gaps instead of fake methods.

```ts
/** Contract:
 * - get: missing → null (never throw for "not found")
 * - delete: missing id → resolve without error (idempotent)
 * - add: reject duplicate id with conflict error type
 */
export interface TodoRepository {
  get(id: string): Promise<Todo | null>;
  add(todo: Todo): Promise<void>;
  delete(id: string): Promise<void>;
}

export class PostgresTodoRepository implements TodoRepository {
  async get(id: string) {
    const row = await this.client.query(/* … */, [id]);
    return row ? mapTodo(row) : null; // ✅ same as libSQL
  }
  async delete(id: string) {
    await this.client.query("DELETE FROM todos WHERE id = $1", [id]);
    // ✅ 0 rows deleted is still success (idempotent)
  }
  async add(todo: Todo) {
    try {
      await this.client.query(/* insert */, [todo.id, todo.title, todo.done]);
    } catch (e) {
      if (isUniqueViolation(e)) throw new ConflictError("TODO_EXISTS");
      throw e;
    }
  }
}
```

```ts
// ✅ Test fake — substitute safely in use-case tests
export class MemoryTodoRepository implements TodoRepository {
  private map = new Map<string, Todo>();
  async get(id: string) {
    return this.map.get(id) ?? null;
  }
  async add(todo: Todo) {
    if (this.map.has(todo.id)) throw new ConflictError("TODO_EXISTS");
    this.map.set(todo.id, todo);
  }
  async delete(id: string) {
    this.map.delete(id);
  }
}
```

When a vendor cannot support a feature, **narrow the port** or expose capabilities—do not stub a lying method:

```ts
export type DbCapabilities = { softDelete: boolean };

// Prefer: softDelete only on ports/adapters that support it
// Not: softDelete() { return; } on MariaDB "to compile"
```

## Frontend (React) — worst practice

Two “storage” implementations that break the UI’s assumptions.

```ts
export interface TodoStore {
  load(): Promise<Todo[]>;
  save(todos: Todo[]): Promise<void>;
}

// ❌ API store: save is durable
export const apiStore: TodoStore = {
  async load() {
    return listTodos(BASE);
  },
  async save(todos) {
    await putTodos(BASE, todos);
  },
};

// ❌ Local store: save pretends to work but drops data
export const brokenLocalStore: TodoStore = {
  async load() {
    return [];
  },
  async save() {
    // "offline support" that never writes
  },
};
```

```tsx
// UI trusts the contract — user loses data with brokenLocalStore
await store.save(next);
showToast("Saved"); // ❌ lie under substitution
```

## Frontend (React) — best practice

Same behavioral contract; UI can swap stores (API vs Capacitor Preferences) safely.

```ts
export interface TodoStore {
  load(): Promise<Todo[]>;
  /** Persists all todos; rejects on failure (never silent). */
  save(todos: Todo[]): Promise<void>;
}

export const apiTodoStore: TodoStore = {
  load: () => listTodos(BASE),
  save: (todos) => putTodos(BASE, todos),
};

export const preferencesTodoStore: TodoStore = {
  async load() {
    const raw = await Preferences.get({ key: "todos" });
    return raw.value ? (JSON.parse(raw.value) as Todo[]) : [];
  },
  async save(todos) {
    await Preferences.set({ key: "todos", value: JSON.stringify(todos) });
  },
};
```

```tsx
// ✅ Same hook works with either store
function useTodoStore(store: TodoStore) {
  const [todos, setTodos] = useState<Todo[]>([]);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    let cancelled = false;
    store
      .load()
      .then((data) => {
        if (!cancelled) setTodos(data);
      })
      .catch(() => {
        if (!cancelled) setError("load failed");
      });
    return () => {
      cancelled = true;
    };
  }, [store]);

  async function persist(next: Todo[]) {
    setError(null);
    await store.save(next); // may throw — UI handles error
    setTodos(next);
  }

  async function addTodo(title: string) {
    const next = [...todos, { id: crypto.randomUUID(), title, done: false }];
    try {
      await persist(next);
    } catch {
      setError("save failed");
    }
  }

  return { todos, error, addTodo };
}
```

### Final use — pick `apiTodoStore` or `preferencesTodoStore`

The page does not care which store you pass. LSP means either substitute works the same way at the call site.

```tsx
// ✅ Composition root: choose the store once
import { Capacitor } from "@capacitor/core";

function createTodoStore(): TodoStore {
  // Web / server-backed → API
  // Native shell → Capacitor Preferences (still durable, still throws on failure)
  if (Capacitor.isNativePlatform()) {
    return preferencesTodoStore;
  }
  return apiTodoStore;
}

// Or choose explicitly for demos / feature flags:
// const store = apiTodoStore;
// const store = preferencesTodoStore;
```

```tsx
// ✅ Page — identical usage for both stores
export function TodosPage({ store }: { store: TodoStore }) {
  const { todos, error, addTodo } = useTodoStore(store);

  return (
    <main>
      {error && <p role="alert">{error}</p>}
      <TodoForm onAdd={addTodo} />
      <ul>
        {todos.map((t) => (
          <li key={t.id}>{t.title}</li>
        ))}
      </ul>
    </main>
  );
}
```

```tsx
// ✅ App entry — wire one or the other (or both in different trees)

// Case A: always persist via Hono API
<TodosPage store={apiTodoStore} />

// Case B: always persist via Capacitor Preferences
<TodosPage store={preferencesTodoStore} />

// Case C: pick at runtime (web vs native)
<TodosPage store={createTodoStore()} />
```

Because both stores honor `load` / `save` (persist or throw), you never write `if (store === apiTodoStore)` inside `TodosPage` or `useTodoStore`.

For visual variants, honor shared props (e.g. every `TodoItem` must accept `aria-label` / keyboard handlers)—a “pretty” card that drops keyboard support is an LSP break for an accessible item contract.

## Side-by-side

| Promise | Worst substitute | Best substitute |
|---------|------------------|-----------------|
| `get` miss | throws vs `null` | always `null` |
| `save` | silent no-op | persist or throw |
| Test fake | different errors | same error types |

## Trade-offs

| Benefit | Cost |
|---------|------|
| Callers stay simple | Stricter design / contract tests |
| Safe fakes in tests | May need smaller interfaces ([04-I.md](04-I.md)) |
